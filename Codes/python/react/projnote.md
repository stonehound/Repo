# This is the notespace for the reactive video project I'm making to promote the engineering design club

Initial Concept:
I want to create a code that generates music that impacts aspects of an animation with user interface to control the music in real-time. 
Other goals include making an analog amplifier with 3D printed body using the speakers in the fabrication room, and adding a microphone or MIDI controller to make the display even more interactive.

Development Notes:
9/12/2025
I originally wanted to use the Adafruit Jam, a mini-computer utilizing the RP2350 microcontroller. This board has an HDMI port and audio jack, which I wanted to use to send the video data to a screen and intake musical sound data via the headphone jack. I wanted to use a FFT to analyze the incoming music, and create a fractal animation that changed in real-time depending on the music. After looking into examples, I found that it could be done although it would rely on using a Pulse Density Modulation Microphone, a digital microphone rather than the audio input jack. I found that the adafruit libraries available were almost exclusively for the output of sound rather than the input of sound. I could use the analog input on the board but I'd almost certainly need to set up an op-amp audio amplifier just to bring the audio signal to line level, avoiding damaging the board by inputing audio with a peak-to-peak voltage greater in range than 0v-3.3v.
In light of this, I began considering a stronger language with broader community support, turning to Python3. I'm working on a 2109 MacBook Air currently but want to complete development on a RaspberryPi 4B 8bg for ease of access to GPIO pins to support user interface.
I began trying to implement the animation of a fractal using numpy and matplotlib, which was quick to succeed in proof of concept, but woefully slow in term of animation speed. While looking for a more seamless means of animating, I came across a potential means of real-time reactive video generation via a reactive coding library called Signified. 
The creator of Signified was using a graphics library for animation called PyCairo, I may try to use this for animation or looking into another animation library, although I imagine PyCairo can be used in conjunction with Signified by design. For the sound synthesis, most of the coding music production languages I've come across like SonicPi or Tidal Cycles rely on synthesis software called SuperCollider. I'm currently trying out a python library called Supriya that enables the use of SuperCollider via Python3 in hopes that I can integrate it with the animation via Signified. 
I'm struggling to get Supriya to access control over SuperCollider, so I'm going to try to pivot to SCAMP(Suite for Computer-Assisted Music in Python) to control SuperCollider instead. Okay so I had trouble getting SCAMP to recognize its own resources, likely a pathway error because SCAMP relies on a lot of other software and I'm guessing they haven't all co-developed over time to support all platforms seamlessly. This is also because I'm trying to run this all through the CLI terminal rather than a GUI IDE like Thonny. In this process, I installed SuperCollider via terminal and now the Supriya library is working. I ran an example code from the Supriya github and got sound out of the laptop speakers as a proof of concept. I look forward to setting all of this up again on the Raspberry Pi in a couple of Days.
On that note, I intend to run a light-weight distribution of Linux for the operating system given I want to dedicate most of the machine's resources to audio and video processing. I was considering DietPi to start as it has Python support and is about as light weight as it comes for a distro that has a desktop. I would prefer to not have a desktop, but it will both speed up project development and spare me the need to code access to the audio interfacing hardware and force a GUI for the animation on a headless Linux distro.

9/14/2025
While I have some progress with Supriya, I'm going to try FoxDot instead as it's fully developed and supported while Supriya is barely a year old at this point. I'm also trying to migrate or at least back up all work onto a github repo for quick redeployment once the new Raspberry Pi 4b arrives. I may try to split screen, having one HDMI port dedicated to live coding and the other to the reactive video being generated.
Cairo can be used to create images, which can be automated to be generated to create a sequence of images that serve as the animation. This will require a lot of work in just setting up the animations, let alone connecting it to FoxDot via Signified. For similar reasons, I'll be trying out Manim for animation and reactivity in conjunction with FoxDot because it has existed longer and has more support and examples. 

9/15/2025
After struggling to get Manim installed on RaspberryPi OS, I had some luck using the Pygame library animating a rectangle with growing height. I now want to use Pyaudio to see if I can get volume data from an input signal in real time.
